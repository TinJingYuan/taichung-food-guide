# 好好吃飯

一人份、一週七餐的靜態食譜與備餐原型。開啟根目錄 `index.html` 即可使用；在本機開發時也可執行 `python3 -m http.server 8000`，瀏覽 `http://localhost:8000`。

## 使用流程

1. 在「菜色總覽」新增、編輯、刪除菜色。它是獨立菜色庫。
2. 在「本週七餐」挑七道想吃的料理，可以重複，不指定哪一天。
3. 在「採買與保存」查看合併食材清單，手動記錄家中現有量、保存方式與包裝標示期限。勾選採買項目只是購物清單標記；買好後請自行更新現有量。
4. 每天到「今天煮什麼」自行瀏覽或抽取本週尚未煮的料理。抽卡不會根據庫存或解凍狀態過濾。
5. 菜卡顯示價格、時間、食材、缺少量、冷凍紀錄、備菜、步驟與營養值；完成一餐時，扣除**已登記**的庫存量。
6. 「費用與營養」顯示食譜每份預估成本、外食差額及已知營養值與自訂參考目標。未填資料標為待補，不視為零。

本週餐次包含當時菜色內容的快照，之後修改或刪除菜色庫，不會更動已選餐次。建立新一週會清空本週餐次及購物勾選，保留菜色庫和家中現有量。

## 資料與限制

- 資料僅存於目前瀏覽器的 `localStorage`；沒有帳號、資料庫或跨裝置同步。清除瀏覽器資料會刪除紀錄。
- 初始菜色的每份價格採使用者提供的估值；炒烏龍麵價格、全部菜色營養值尚無完整資料。烹煮時間、步驟與部分食材單位是可編輯的示例，請按實際食譜修正。
- 「每份成本」是食材分攤估價，**不是**實際購物金額；購物包裝數量與價格未建模。外食差額也僅是估算。
- 食材只按名稱與單位合併，例如「一份」與「120 g」不會自動換算。若同名食材實際是不同規格，需在菜色庫中統一資料。
- 冷藏期限屬一般參考，優先看包裝、購入時間、冰箱溫度與食材狀態。冷藏表參考 [FoodSafety.gov](https://www.foodsafety.gov/food-safety-charts/cold-food-storage-charts)。
- 營養比較只涵蓋本週所選的七餐，不表示完整每日攝取量；參考目標需自行輸入。

## 後續資料庫化

現有狀態適合作為操作原型。若要作為資料庫系統實作，可把菜色、食材、食譜食材用量、每週計畫、餐次快照、採買與庫存拆為關聯資料表；由後端 API 取代 `localStorage`，再加入登入與跨裝置同步。這一版不宣稱已連接 SQL Server。
